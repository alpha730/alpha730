# Setup: manual steps for you

Steps 1 and 2 are done: `alpha730/alpha730` exists, and the workflow has run once. The rest only you can do.

## 1. Create the repo and push (done)
For reference only:
```sh
git remote add origin https://github.com/alpha730/alpha730.git
git push -u origin main
```
`node_modules/` and `preview/` are git-ignored.

## 2. Enable the live-stats workflow (done)
1. Repo **Settings > Actions > General > Workflow permissions**: choose **Read and write permissions**.
2. **Actions** tab > "Update profile stats" > **Run workflow**.
3. It then runs daily and commits only files under `assets/` with the message `chore: refresh profile stats [skip ci]`.

**After pushing the comic design, run the workflow once by hand.** The Long Watch's 52 weekly torches stay unlit until it does, because the saved data from earlier designs has no 52-week series (the 12-month total is already there). The workflow saves the numbers it fetches in `assets/live-data.json`, so later rebuilds (`npm run build`) re-render the live panels (`watch.svg`, `languages.svg`, `activity.svg`) without losing the data.

**Limitations**
- **The live stats count public contributions only.** The built-in `GITHUB_TOKEN` can't see your private contributions. A personal access token could, but I deliberately didn't use one, so no secrets are stored.
- The contribution total and the torches cover the **last 12 months** (the window the contributions API returns), not your all-time record.
- GitHub pauses scheduled workflows after 60 days without repo activity. Check the Actions tab if the stats stop updating, and re-enable the workflow if needed.
- The comic SVGs paint their own newsprint backgrounds, so they look the same in GitHub's light and dark themes.
- The workflow uses `actions/checkout@v5` and `actions/setup-node@v5`, both verified to exist and to run on Node 24. Newer majors (v7) exist if you want to move up later.

`Prompt-injection-Tester-`, `sih-project`, `ASHA-Voice-Logging-Agent`, `DUO-Game`.

GitHub redirects the old URL, but fix the links anyway. `README.md` is generated by the build, so its links update too.

## 5. Fill the missing metric (The Raven's Eye, `sih-project`)
The `sih-project` card (II · The Raven's Eye) shows no metric on purpose, because no measured number exists yet. When you have a real one:
1. Set `result` on mission 2 in `profile.config.json` to a short sentence, as the other missions do.
2. Run `npm run build`. The README is regenerated, and the `<!-- TODO: add metric -->` comment disappears with it.

## 6. Check The Raven's Eye stack wording
I derived the `sih-project` chapter's stack from the repo itself (`pyproject.toml` and README). The chapter lists **Python, PyTorch, LangGraph, Rasterio** and "SAR + optical". The repo doesn't use LangChain, GDAL or RAG, and it never mentions multispectral. Edit `profile.config.json` if you want different wording.

## Fonts and licences
Both fonts are under the **SIL Open Font License 1.1**. The licence texts are in `scripts/art/fonts/`, beside the font files:
- **Bangers** by Vernon Adams (`Bangers-Regular.ttf`, `OFL-Bangers.txt`), used for titles and sound effects.
- **Comic Neue Bold** by Craig Rozynski and Hrant Papazian (`ComicNeue-Bold.ttf`, `OFL-ComicNeue.txt`), used for body text.

GitHub serves README SVGs as images, and images can't load web fonts. So no SVG contains text or a font: every string is drawn as glyph outlines (paths). The original strings stay in each `<img>` alt and each SVG's `<title>`/`<desc>`.

The outlines come from a baked glyph atlas, `scripts/lib/glyphs.json` (outlines, advances and kerning for printable ASCII plus `· © – — … → ’ “ ”`). The atlas lets the GitHub Action draw text without `npm install`. Rebuild it only if you change fonts or need a new character:
```sh
npm run glyphs     # uses opentype.js (dev-only) -> scripts/lib/glyphs.json
```
A character missing from the atlas is drawn as `?`.

## Regenerating the pixel art (dev-only)
The approved pixel art is committed in `scripts/art/pixel/`: `hero.png` 1584x864, the four chapter scenes 768x472, and `chain.png` 600x544, all rendered at 2x. The build embeds these exact files in the SVGs. The GitHub Action never runs the generators.

To regenerate them you need Python 3 with Pillow and numpy:
```sh
pip install pillow numpy
mkdir -p art-out
python scripts/art/scenes.py art-out   # wall, raven, scroll, dragon, chain (+ an unused parchment map)
python scripts/art/hero.py art-out     # hero_full.png and hero_pixel.png
```
Then compare the results with `scripts/art/pixel/` and copy over only what you want to change. `hero_pixel.png` becomes `hero.png`. Then run `npm run build`. The committed PNGs are the source of truth, because the generators aren't fully reproducible. Checked on 2026-11-17 with Pillow 11.2.1 and numpy 2.4.6: `hero`, `raven` and `chain` came out pixel-identical, but `wall` (0.04% of pixels), `dragon` (0.5%) and `scroll` (9.5%) differed from the approved files. The approved design mockups are in `scripts/art/mockup/` (design-canvas files, kept for reference only).

## Rebuilding locally
```sh
npm install        # dev tools only: resvg (PNG previews) and opentype.js (glyph atlas)
npm run build      # regenerate every SVG in assets/ and README.md from profile.config.json
npm run render     # PNG previews in preview/ (desktop + 330px, hero filmstrip, README composites)
npm run validate   # README, asset, text-size and scope checks
```
The same config, pixel art and glyph atlas always produce the same SVGs.

Live-stat data comes from `node scripts/live-stats.mjs`. It needs a `GITHUB_TOKEN` in your environment, which the workflow supplies, and it refuses to run without one.
